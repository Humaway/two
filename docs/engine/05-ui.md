### 1.2 Design rules the code follows (keep them in TWO)

1. **Game time, not wall time.** Every timer (tweens, typewriter, beats, toast, pop-up `dur`, spinner tick, HUD
   counting) advances in `ui.update(dt)`, which runs once per fixed 1/60 s tick (36-main.js:26). Pausing
   (`clock.paused`) freezes it, and the NO-held fast-forward (`clock.scale = 3`) speeds it up. CSS transitions and
   keyframes (letterbox slide 0.4 s, toast fade, pop-up pop/shake, spinner, bob arrow) run on wall time.
2. **Per tick, only `opacity`, `transform` and text change** (header comment, line 4). DOM nodes are created once and
   pooled: pop-up windows (389), choice buttons (245), menu buttons (664), inventory slots (104).
3. **Skip-safe.** While `flow.skipping` is true, `say`/`choose`/`ask` resolve at once, `title`/`actCard` return,
   `fade`/`flash`/`hud.animate` jump to their end values, buttoned pop-ups auto-answer. See §11.
4. **Autoplay-safe.** Under `?autoplay=1` every modal UI answers itself within 0.15–0.5 s. See §11.

### 1.3 `ui.update(dt)` order (141-155)

```
ui.update(dt)                       called from tick(), after menus.update(), before clock.step()   36-main.js:22-28
 ├─ opacity tweens (fade, flash, tcard, acard)
 ├─ toast timer (2.2 s)
 ├─ objective.update()              hide in cutscenes / when the option is off
 ├─ hud.update(dt)                  battery / bars counting
 ├─ if the inventory panel is open: invUpdate(dt); RETURN      ← dialogue and pop-ups freeze while it is open
 ├─ say.update(dt)                  typewriter, YES, choices, auto-advance
 └─ popup.update(dt)                ages, progress bars, spinners, dur, YES / ← → / NO for the top pop-up
```

Because `ui.update` runs **before** `clock.step()` (flow's `tick`, hotspots, minigame `update`), the dialogue box and
the top buttoned pop-up see each YES press first. When they `input.consume('yes')`, hotspots and minigames never see it.

### 3.1 The opacity tween engine (`fadeTo`, 16-21; private)

```js
function fadeTo(el, to, dur) {
  for (let i = 0; i < tweens.length; i++) if (tweens[i].el === el) { const o = tweens[i]; tweens.splice(i, 1); o.res(); break; }
  if (!(dur > 0) || U.skipping()) { el._o = to; el.style.opacity = to; return Promise.resolve(); }
  return new Promise((res) => tweens.push({ el, a: el._o, b: to, dur, t: 0, res }));
}
```

- Used by `#fade`, `#flash`, `#tcard`, `#acard`. Current opacity lives in `el._o` (initialised at line 14: fade 1, others 0).
- **A new tween on the same element replaces the old one and resolves the old promise immediately**, while the
  opacity is still mid-way. Code that awaited the old fade continues early.
- Linear interpolation in `ui.update` (142-148). The promise resolves on the tick it reaches the target.
- **A tween already running when a skip starts is not hurried.** Only *new* calls are instant. A `{fade, dur: 2}` step
  in progress when Skip Scene is chosen still takes its remaining game time.

### 3.2 `ui.fade(to, dur = 0.5, color)` (30-35)

| Arg | Meaning |
| --- | --- |
| `to` | `'out'` = 1 (cover), `'in'` = 0 (reveal), or any opacity 0..1 |
| `dur` | Seconds of game time. `0` = instant |
| `color` | CSS colour for `#fade`'s background. **Omitted and `to > 0` → reset to `#000`**. Omitted and `to == 0` → keeps the current colour, so `{fade:'out', color:'#fff'}` followed by `{fade:'in'}` fades back from white |

Reduce Flashing (33): when `options.reduceFlashing`, fading **up** to a colour matching `/^#f/i` takes at least 1.2 s.
The test is crude: `'#ff0000'` is slowed too, `'white'` or `'rgb(255,255,255)'` is not. Use `'#fff'` for white.

`flow.start` uses it for scene transitions: `await ui.fade(1, 0.5)` … `ui.fade(0, 0.8)` without awaiting
(`11-flow.js:549, 571`). The first step runs in the same tick, so an opening `{fade}` step wins.

### 3.3 `ui.flash(dur = 0.6, color = '#fff')` (36-42)

- Normal: `#flash` snaps to opacity 1 in `color`, then fades to 0 over `dur`.
- Reduce Flashing: ramps from its current opacity to 0.35 over `0.4·dur`, then to 0 over `1.2·dur` (total `1.6·dur`).
- Skipping: opacity 0 at once.
- `#flash` (z 9) is under `#fade` (z 10). A flash during a full fade-out is invisible.

### 3.4 `ui.letterbox(on)` (43)

Toggles `#ui.lbon`. The bars are `height: max(0px, calc((100vh - 100vw / 2.35) / 2))` and slide 0.4 s with a CSS
transition (wall time, not skipped, not paused). On screens wider than 2.35:1 they have zero height. `playCutscene`
turns them on and off itself (`11-flow.js:98, 105`).

### 3.5 `ui.title(text, dur = 2.5)` (44-48)

```js
async title(text, dur = 2.5) {
  if (U.skipping()) return;
  tcard.textContent = text;
  await fadeTo(tcard, 1, 0.5); await wait(Math.max(0, dur - 1)); await fadeTo(tcard, 0, 0.5);
},
```

Centred, upper-cased by CSS, `letter-spacing: .28em`, 21 px, z 11 (over the fade). Total time ≈ `max(dur, 1)`. Used for
date and time cards ("Tuesday, 6 October 1987"). Skipping shows nothing.

### 3.6 `ui.actCard(text)` (49-55)

Splits `text` on the first `' — '` (space, em dash, space): the left part goes in `#acard b` (46 px, wide tracking), the
right part in `#acard i` (22 px), with a yellow `hr` between. It fades in 0.8 s, holds 2.8 s and fades out 0.8 s
(4.4 s in total) on its own black background. `flow.start` awaits it for every id in `ACTS` while the screen is faded
out (`11-flow.js:567`). Skipping shows nothing.

### 3.7 `ui.paintCard(cv, kind, data)` and `ui.card(kind, data)` (57-76)

```js
paintCard(cv, kind, data) {
  const f = CARDS[kind];
  if (!f) { console.warn('RUE: no CARDS.' + kind); return null; }
  const s = f.size || [800, 600];
  if (cv.width !== s[0]) cv.width = s[0];
  if (cv.height !== s[1]) cv.height = s[1];
  const cx = cv.getContext('2d');
  cx.setTransform(1, 0, 0, 1, 0, 0); cx.clearRect(0, 0, s[0], s[1]);
  cx.save(); f(cx, s[0], s[1], data || {}); cx.restore();
  return s;
},
```

- `paintCard` paints any canvas at the painter's **native** size `CARDS[kind].size` (default `[800, 600]`). It resizes
  the canvas only when the size differs, so the same canvas can be repainted cheaply. `data` defaults to `{}`.
- `ui.card(kind, data)` paints into the single `canvas#card` and shows `#cardwrap`. `ui.card(null)` (or any falsy kind)
  hides it. An unknown kind warns and leaves the previous card as it was.
- **Sizing** (73): `k = min((lbon ? 0.62 : 0.7) · innerHeight / h, 0.86 · innerWidth / w)`. The CSS size is
  `round(w·k) × round(h·k)`, centred on the viewport. `k` can exceed 1, which **upscales a 1× bitmap** and blurs it on
  large or high-DPI screens. The size is computed once per call: a window resize does not refit the card.
- Who hides it: the next `shot` step without `card`, the end of the outermost cutscene, `flow.skip()`, `flow.start`,
  `ui.reset` (`11-flow.js:103, 118, 551, 598`). **A card shown with `c.ui.card()` inside a `do` step is not tracked by
  flow's `cardOn`**. Clear it yourself with `ui.card(null)` (Rue's content always does, e.g. `28-content…:62-65`).
- Animated cards are done by repainting: 8 repaints 0.07 s apart (`24-content…:36`). Each repaint runs the whole painter
  (gradients, `measureText`, sometimes new canvases), so do not call it every tick.

### 3.8 `ui.toast(text)` (77)

Sets `#toast` text, adds `.show`, starts a 2.2 s game-time timer (decremented in `ui.update` even while the inventory is
open). One toast at a time: a new one replaces the text and restarts the timer. Bottom right; lifted above the dialogue
box while `talking`; under the pause button on touch. z 11, so it shows over a black fade.

### 3.9 `ui.prompt(text)` (78-86)

The interaction pill, bottom centre. It **dedupes**: calling it with the same string as last time does nothing, so it is
safe to call every tick. `null`/`''` hides it.

```js
const m = /^(YES|NO)\b\s*(?:—\s*)?(.*)$/.exec(text);
```

`'YES — Examine'` → yellow `YES` pill + "Examine". `'NO — Torch off'` → grey `NO` pill + "Torch off". `'YES'` alone → a
pill with no label. Anything else (`'Left stick — Move · A — YES'`) is plain text with no pill. The separator must be an
**em dash**. Hidden (opacity 0) while the dialogue box is up. `flow`/`hotspots` call `ui.prompt(null)` whenever control
changes. Content occasionally pokes `#prompt`'s style directly (`20-minigames…:385`).

### 3.10 `ui.swapIndicator(activeId, otherId)` (87-94)

Bottom left: `img.a` (64 px, yellow border) = `portraitURL(activeId)`, `img.b` (40 px, behind) = `portraitURL(otherId)`
or hidden, and a key label chosen **at call time** from `input.scheme`: `'Y'` (pad), `'SWAP'` (touch), `'TAB'`
(keyboard). It does not update if the player changes device later. `ui.swapIndicator(null)` hides it. Flow drives it
(`showSwap`, `11-flow.js:65-68`): shown only while roaming, with swap enabled and a second playable.

### 3.11 `ui.inventoryPanel(spec)` (97-132, 158-202): the BAG

Modal. `spec`:

| Field | Type | Meaning |
| --- | --- | --- |
| `items` | `[{ id, name?, icon? }]` | Slots, in order. `name` falls back to `ITEMS[id].name`, then `id`. `icon` falls back to `ITEMS[id].icon` |
| `onExamine(id)` | fn | Examine chosen |
| `onUse(id)` | fn | Use chosen |
| `onCombine(a, b)` | fn | Combine chosen, with the two item ids |
| `onClose()` | fn | Closed with NO / the inventory key / autoplay. **Not** called after Examine/Use/Combine |

Returns `{ close() }` (closes only if this spec is still the open one). `ui.inventoryPanel(null)` closes without calling
`onClose` and returns `null`.

- **Icons** are `icon(cx, 96, 96)` canvas painters, called once per slot per open. Without one, a navy rounded tile with the
  item's yellow initial is drawn (120-124). Rue's content wraps them in a 100×100 unit helper
  (`28-content…:59`: `const icon = (fn) => (c, w, h) => { c.save(); c.translate(w / 2, h / 2); c.scale(w / 100, h / 100); fn(c); c.restore(); }`).
- The description line shows `ITEMS[id].desc` (or the name). In combine mode it reads "Combine A with… B" (168).
- Empty bag: "Nothing in your pockets." (128).

Input state machine (`invUpdate`, 180-202). Left/Up = previous, Right/Down = next. All four directions are consumed.

| Mode | ← → | YES | NO | Inventory key |
| --- | --- | --- | --- | --- |
| `items` | move the slot | → `acts` (if any items) | close (`onClose`) | close |
| `acts` | cycle Examine / Use / Combine | Examine → close + `onExamine(id)`; Use → close + `onUse(id)`; Combine → `combine` mode (needs ≥2 items, else `clunk`) | → `items` | close |
| `combine` | move the slot, skipping the first pick | if not the first: close + `onCombine(first, sel)` | → `acts`, selection back to the first | close |

Mouse/touch: clicking a slot selects it and enters `acts` (in `combine` mode it picks the second item). Clicking an
action button runs it on the current selection (178).

**While the panel is open, `ui.update` returns before `say.update` and `popup.update`**: the typewriter, pop-up timers
and pop-up input all freeze, and a pending `say` cannot resolve even when skipping. `11-flow.js:381-403` shows the
intended wrapper: `inventory.open()` disables the player, and every callback calls its own `close()`. Under autoplay the
panel closes itself after 0.5 s (182).

## 4. Dialogue: `say`, `choose`, `ask` (207-378)

One dialogue box (`#dlg`) and one state object `D` (212-213). **One request at a time**: starting a `say`, `choose` or
`ask` while another is pending resolves the pending one first (with `undefined`) (264, 322, 334). Never put two `say`s in
the same `par`.

### 4.1 `say(id, text, o = {})` → `Promise<void>` (261-285)

| Option | Default | Effect |
| --- | --- | --- |
| `name` | `CHARACTERS[id].name`, else `String(id).toUpperCase()` | Name label (`{ say: 'hartigan', …, name: 'PROFESSOR HARTIGAN' }`, `27-content…:540`) |
| `tag` | `''` | Small text after the name, e.g. `tag: 'intercom'` (`23-content…:176`). Rendered lower-case, not italic (CSS 88) |
| `portrait` | shown | `false` hides the face (`noface`) |
| `speed` | `'normal'` | `'slow'` / `'normal'` / `'fast'`, **relative to the player's Text speed option** (below) |
| `auto` | `0` | Seconds after the line has fully typed before it advances on its own. `0` = wait for YES |
| `censor` | `false` | `true` or a pop-up message string: the swearing censor (4.1.6) |
| `expr`, `act` | — | Handled by the flow step, not by `say`: `world.actor(id).setExpr(expr)` / `.play(act)` before the line (`11-flow.js:123-125`) |

`text` is coerced with `String(text ?? '')`. If `flow.skipping` is already true, `say` resolves immediately and shows
nothing (262).

#### 4.1.1 Beats: `^`

```js
// '^' = a beat: pause CONFIG.beat there, render nothing, collapse the doubled space
for (let k = 0; k < text.length; k++) {
  const c = text[k];
  if (c === '^') { if (text[k + 1] === ' ' && (out === '' || out.endsWith(' '))) k++; beats.push(out.length); continue; }
  out += c;
}
```

- Each `^` records a pause of `CONFIG.beat` (0.8 s) at that character position and is not displayed.
- `"Post-it. On the monitor. ^ It's a whole system, Chase."` (`23-content…:308`) types "…monitor. " then pauses, then
  "It's…": the space after `^` is dropped so the text has single spaces. `"Brennan. ^Byrne."` works too.
- During a beat the speaker's mouth stops (`world.talk(id, false)`) and restarts after it.
- `^^` = two beats (1.6 s). A `^` at the very **end** of a line does nothing: the line completes when the last
  character is typed.
- A YES press during a beat completes the whole line.

#### 4.1.2 Typing speed

`cps = CONFIG.text[o.speed] × CONFIG.text[options.textSpeed] / CONFIG.text.normal` (276), with
`CONFIG.text = { slow: 24, normal: 48, fast: 110 }`:

| `o.speed` \ option | Slow | Normal | Fast |
| --- | --- | --- | --- |
| `'slow'` | 12 | 24 | 55 |
| `'normal'` | 24 | 48 | 110 |
| `'fast'` | 55 | 110 | 252 |

Several characters can be appended in one tick. Characters are appended to a single text node (`node.appendData`), so
there is no per-character DOM allocation (304). At `'fast'` (either the line or the option) only every other letter
blips.

#### 4.1.3 Voice blips, mouths, ducking

- A blip plays per **letter**: `0-9`, `A-Z`, `a-z`, or any code point from U+00C0 to U+1FFF (305). Spaces and
  punctuation are silent. `AUDIO.blip(id, rising)` rate-limits each voice to its syllable rate on the audio clock
  (`03-audio.js:852`), so fast text never machine-guns.
- **Question inflection:** if the line ends with `?` (optionally followed by spaces, `…`, `—`, quotes or `)`), the last
  ~6 characters blip with the rising variant (277, 306).
- Unknown speaker ids blip with `V[id]`, else `V[first part before '_']`, else the `student` voice (`03-audio.js:849`).
- Mouths: `world.talk(id, true)` while typing, `false` at the end and during beats. A duet id whose
  `CHARACTERS[id].voice.also` is set (`luka_chase`) moves both actors: `D.talk = id.split('_')` (281).
- **Ducking:** showing the box calls `AUDIO.duck(true)` (music bus × `CONFIG.duck` = 0.6, the "40% duck"); hiding it calls
  `AUDIO.duck(false)` (221, 226). `duck` is a plain boolean, not a counter.

#### 4.1.4 Advancing: YES, NO and auto

| Input | While typing | After typing |
| --- | --- | --- |
| YES (key, pad A, touch YES, or a click on the box or anywhere not a button) | Completes the line instantly (355). The press is consumed, so advancing needs a second press | Resolves the `say` (362). The bobbing ▼ (`.more`) shows that it is waiting |
| NO | Not handled by the dialogue box | Not handled |
| NO **held** inside a cutscene | `clock.scale = 3` (`11-flow.js:445`): the game runs three ticks per frame, so typing, beats, `auto` timers, waits, camera moves and tweens all run 3× faster | same |
| `o.auto > 0` | — | Resolves `auto` seconds after the line finished typing (361) |

The fast-forward only exists while `flow.cutscene` is true (`cutDepth > 0`). Hotspot text played with `say` outside a
cutscene (`11-flow.js:299-304`) is not fast-forwarded. Blips still throttle on the audio clock under 3×.

#### 4.1.5 The box between lines

`finish()` (228-232) resolves the promise but leaves the box up. `say.update` hides it after 0.07 s with no new request
(350), so consecutive lines never flicker and music is not un-ducked between them. `header()` (233-240) only reloads the
portrait `src` when the speaker changes.

#### 4.1.6 The censor (`censor: true | 'message'`) (278-297)

- The line is typed only to `floor(0.75 · length)` characters, **unless it already ends in `—`**, in which case it is
  typed in full (the script did the cut).
- When typing stops: `state.flags.seen_swearing = true`, then a pop-up slams in: `{ msg: censor string or 'Language
  detected. This interaction has been flagged for coaching.', icon: 'warn', buttons: ['OK'], shake: true, at: { actor:
  speaker } }` (or `'center'` if the speaker has no actor). For duet ids the first speaker is used.
- The `say` resolves when that pop-up's OK is pressed, or, if a cutscene camera is active (`cam.cutscene`), after 1.2 s
  at most. The pop-up itself stays until OK.
- While waiting, `say.busy()` is false, so the pop-up receives YES.
- Rue's content puts it back if dismissed (`cuss()`, `24-content…:57-61`).

### 4.2 `choose(labels, o = {})` → `Promise<number>` (321-332)

| Option | Default | Effect |
| --- | --- | --- |
| `disabled` | `[]` | Indices drawn grey (`.dis`). Picking one plays `clunk` and does nothing |
| `test` | — | Index the autoplayer and the skipper pick (if not disabled) |

- **If the box is still up** (a `say` just finished, within the 0.07 s linger), the options appear **under that line**,
  keeping its name and portrait. If the box had closed (for example a `wait` came between), it opens with no name, no
  portrait and no text (326).
- The first enabled option is preselected. Up/Down move with wrap-around (disabled ones can be highlighted), YES picks.
  Mouse: hovering highlights, clicking picks. NO does nothing.
- Resolves with the 0-based index. The flow step sets `flow.result` and, with `flag`, `state.flags[flag] = index`.
- Skipping or autoplay (after 0.3 s): `test` if set and enabled, else the first enabled index, else 0 (318).

### 4.3 `ask(question, o = {})` → `Promise<boolean>` (333-345)

| Option | Default | Effect |
| --- | --- | --- |
| `yesDisabled` / `noDisabled` | `false` | That pill is greyed and only `clunk`s |
| `test` | `true` | Autoplay/skip answer. If it points at a disabled answer, the other one is used (319) |

- No name, no portrait. The question appears **instantly** (no typewriter, no blips), then two pills: `YES` (always
  filled yellow) and `NO`. "Put the kettle on? [YES] [NO]" is the canonical use.
- The YES key answers `true`, the NO key answers `false`. There is no left/right selection. Mouse: click a pill.
- Flow step: `{ ask: 'Flip it?', yes: [...], no: [...] }` (`25-content…:34`). Hotspots: `{ ask: { q, yes, no, … } }`.

### 4.4 `say.busy()`, `say.reset()`, `say.update(dt)`

| Member | Lines | Meaning |
| --- | --- | --- |
| `say.busy()` | 347 | `true` while a say/choose/ask is pending, except during the censor wait. **`popup.update` ignores keyboard input while it is true** |
| `say.reset()` | 348 | Drops the pending request **without resolving it**, stops mouths, hides the box. Used by `ui.reset` (title/quit) only; the stale promise just hangs, which is fine because flow bumps its generation |
| `say.update(dt)` | 349-376 | Called by `ui.update`. Skipping resolves the current say (353), choose (367) or ask (372) on the next tick |

### 4.5 Gotchas

- `say` never consumes NO. In an `ask`, a NO press answers *and*, if held inside a cutscene, fast-forwards what follows.
- A `choose` right after a `say` with any gap > 0.07 s loses the line above the options. Put them back to back.
- Speaker ids are also used as actor ids for mouths (`world.talk`), `expr`/`act` cues and the censor pop-up. A speaker
  with no actor simply has no mouth.
- `'^'` stays in the source text. `tools/check-lines.mjs` normalises the spacing around it.

## 5. `popup(spec)`: JARVIS pop-ups (381-514)

Pooled DOM windows in `#pops`. Each pooled entry is built once from a fixed HTML template (385-387):
`.jvw > .jv > (.jv-bar > .jv-logo "JARVIS", .jv-t, .jv-x ×) + (.jv-body > .ic, .jv-msg) + .jv-spin + .jv-prog + .jv-btns`.

### 5.1 Spec options (436-482)

| Option | Default | Effect |
| --- | --- | --- |
| `msg` | `''` | Message text (`textContent`; `\n` breaks lines) |
| `title` | `'JARVIS'` | Title-bar text after the logo. The value `'JARVIS'` shows an empty title (the logo already says it). `'STORAGE FULL'`, `'JARVIS Autocorrect'` |
| `icon` | `'warn'` | `'warn'` (yellow triangle "!"), `'error'` (red circle ✕), `'info'` (blue circle *i*), `'none'` (hidden). Any other string becomes a class with no glyph |
| `buttons` | `['OK']` | Button labels, left to right in the footer. `[]` = no buttons, no footer, and **no input at all** (only `dur`, `.close()` or `popup.clear()` remove it) |
| `at` | stacked centre | Position (5.3) |
| `w` | 340 px (CSS) | Width in px (still capped at `100vw - 20px`) |
| `cls` | — | Extra classes on `.jv`: `'big'` (460 px, 16 px text), `'crash'` (pink body), or your own |
| `shake` | `false` | Shake-in animation (`jvshake`, 0.42 s) instead of the pop-in |
| `spinner` | `false` | Shows the spinner and plays `tick` (vol 0.3) once per second of the pop-up's life |
| `progress` | — | `{ from = 0, to = 100, dur = 1 }`: a bar animating linearly from `from` to `to` over `dur` s with a rounded "%". If both ends are ≤ 1 they are fractions. `from > to` runs backwards. It does not close the pop-up |
| `dur` | `0` | Auto-close after `dur` s of game time; `done` resolves with `-1` |
| `dodge` | — | Array of button indices that **run away** (5.4). Rue's "Buttons that run away" bug |
| `ding` | `true` | `false` suppresses the `ding` SFX on open |
| `z` | `0` | Layer: `zIndex = z·10000 + sequence`. Later pop-ups are on top within the same layer |

### 5.2 Return value: `{ el, done, close }`

| Field | Meaning |
| --- | --- |
| `el` | The pooled `.jvw` wrapper. `el.firstChild` is the `.jv` window (`23-content…:92` animates it; `32-content…:447` appends extra `span.jv-b`s into `.jv-btns`) |
| `done` | `Promise<number>`: the 0-based index of the button pressed, or `-1` when closed by `close()`, `dur`, or `popup.clear()` |
| `close()` | Closes with `-1`. Guarded by a token: it does nothing if the window has since been reused for another pop-up |

**Pool hazards.** After `done` resolves, `el` may already belong to a later pop-up. Do not keep using it. On reuse
`popup()` resets the window's class, width, title, icon, message, spinner, progress, buttons, position and z-index, but
**not** anything else you changed (inline styles on children, extra nodes outside `.jv-btns`, running Web Animations).
Undo your own changes.

### 5.3 Positioning (462-472)

| `at` | Position |
| --- | --- |
| omitted | Screen centre, plus 18 px right and down for every other open *stacked* pop-up (mod 14): a cascade |
| `'center'` | Exact centre, not part of the cascade |
| `[x, y]`, both ≤ 1 | Fractions of the viewport: `[0.5, 0.44]` |
| `[x, y]`, otherwise | **Percentages**: `[28, 40]` = 28% / 40%. A mixed pair such as `[0.5, 50]` is read as percentages (x = 0.5%) |
| `{ actor: id }` | Centred on that actor's head (`a.headPos`), re-projected every rendered frame by `popup.render` and restyled only when it moves more than 0.4 px. If the actor is missing it stays at the screen centre |

The window is centred on the point (`translate(-50%,-50%)`). Positions are CSS pixels computed once: a resize does not
move a pop-up (except actor-tracked ones). For a fixed world point, project it yourself once:
`c.cam.project(v)` and pass fractions (`patience()`, `24-content…:41-44`).

### 5.4 Input (486-511, 398-416)

Each tick, after ageing all pop-ups, `popup.update` finds the **top pop-up = the open one with buttons and the highest
z** (normally the newest). Only that one takes keyboard/pad/touch input, and only while `say.busy()` is false:

| Input | Effect on the top pop-up |
| --- | --- |
| YES | Presses the focused button (focus starts on button 0). If that button is a runaway that has not given up, it dodges instead |
| ← / → | Moves the focus (only when it has 2+ buttons) |
| NO | Presses the first button labelled exactly `'NO'` or `'Cancel'`. **Disabled while `flow.cutscene`** (NO is the fast-forward there). If there is no such button, NO is not consumed |
| Mouse click on a button | Presses it, at any time, on any pop-up (even while `say` is busy) |
| Mouse click on a pop-up's body | Becomes a YES press (`.jv` has no `data-noyes`) → presses the top pop-up's focused button |
| Hover | Focuses the button |

**Runaway buttons (`dodge`).** On hover, a runaway button jumps 60 px away from the side the pointer entered (reversed
if it would end up more than 130 px from home), first up 14 px, then down 10 px. A YES press on a focused runaway makes
it jump 60 px left. After **two** dodges it gives up and can be pressed. Under autoplay or skipping the first
non-runaway button is chosen.

### 5.5 Lifecycle, `popup.clear()`, `popup.count()`, `popup.render`

- Closing hides the wrapper, bumps its token, returns it to the pool and resolves `done` (428-434). The pool only grows
  to the largest number of pop-ups open at once.
- `popup.clear()` closes every open pop-up with `-1`. Called by `ui.reset`, `flow.start`, `flow.skip`, and
  `{ popup: …, clear: true }`.
- `popup.count()` = number open. Rue uses it to test whether a censor pop-up was dismissed.
- `popup.update(dt)` is called by `ui.update`; `popup.render()` runs on the `render` event (registered by `ui.init`).
- Un-hiding a pooled window restarts its CSS pop/shake animation (476).

### 5.6 Gotchas

- **`buttons: []` pop-ups are immortal** unless you pass `dur`, keep the handle and `close()` it, or clear. The door
  spinner is the pattern: `const p = popup({ …, spinner: true, buttons: [] }); await …; p.close();`
  (`11-flow.js:323-327`).
- The flow step does not run while skipping, so `{ popup, wait: true }` leaves `flow.result` at its previous value.
- Pop-ups opened from a `do` step during a skip are not prevented. Guard them with `if (c.flow.skipping) return;` (every
  Rue helper does). Buttoned ones are auto-answered on the next tick, but button-less ones stay up.
- Input goes to the **newest** pop-up, not the oldest.
- `say` blocks keyboard input to pop-ups. A buttoned pop-up opened under running dialogue waits until the dialogue ends
  (or a click).
- Pop-ups are under the letterbox bars and the dialogue box (§2.1).

## 6. `hud`: the 1987 phone status pill (517-560)

The HUD model is **`state.battery`** (0-100 or `null`) and **`state.bars`** (0-4 or `null`). Both are saved with the game.

| Member | Signature | Effect |
| --- | --- | --- |
| `hud.show()` | → `undefined` | Re-renders from `state` (521-531) |
| `hud.set(v)` | `v = null \| { battery?, bars? }` | `null`/falsy → both `null` (hidden). Otherwise updates only the keys present, then `show()`. **Cancels running animations without resolving their promises** (535) |
| `hud.animate(v, dur = 1)` | → `Promise` | Counts each key one integer step at a time to its target, `dur / steps` seconds per step, re-rendering each step. A `null` start counts from 0. Skipping jumps there |
| `hud.update(dt)` | | Called by `ui.update` |

Rendering rules (`show`):

| State | Display |
| --- | --- |
| both `null` | `#hud.off` |
| `battery` set | Fill `scaleX(max(0.07, b/100))` (0 when b = 0), text `b%`, `.low` (red) at ≤5% |
| `bars` = k | the first k of 4 bars lit |
| `bars === 0` and `battery` set | "No Service" in pink |
| `battery == null` | `.nobat`: bars only, no battery, no % and no "No Service" (Rue 3.8) |

Steps: `{ hud: { battery: 1, bars: 0 } }`, `{ hud: { bars: 4 }, anim: 2 }`, `{ hud: null }`. A scene's `hud` field is
applied at scene start; without it, the HUD shows the saved state (`11-flow.js:562`). A `stare` hides it with
`visibility:hidden` (`11-flow.js:203`).

**Gotchas:** `animate` only works for integers (a fractional target never resolves). `set()` during an `animate` leaves
the awaiting code hanging forever.

## 8. `portraitURL(id)`: dialogue portraits (583-633)

`portraitURL(id)` → a `data:image/png` URL of a 128×128 canvas, cached per id. Used by the dialogue box and the swap
indicator.

Resolution order (`canvasFor`, 610-629):

1. A baked canvas (`portraitURL.bake(id, canvas)`): boot renders every `LOOKS` id's 3D bust under the fixed light rig and
   bakes it (`36-main.js:60-92`; see `01-core.md` §8.4).
2. Duet ids (`CHARACTERS[id].voice.also`): left half of `a` + right half of `b` from `id.split('_')`, with a yellow
   divider.
3. Aliases (585): `student → student_a`; `voice`, `operator`, `assistant → null` (silhouette). The alias table is private.
4. A live actor's painted face texture (`a.rig.face.canvas`), or, if a `LOOKS` entry exists,
   **`buildCharacter(look).face.canvas`, which builds a whole rig just for its face**.
5. A silhouette on the navy gradient (with yellow sound arcs for `operator` and `voice`).

`portraitURL.bake(id, canvas)` replaces the canvas and drops the cached URL. The dialogue box only reloads `src` when the
speaker changes (239), so re-baking the current speaker shows on their next line after someone else's.

**Gotcha:** step 4 is a mid-game hitch, and possibly a shader compile, for any id that has a `LOOKS` entry but was not
baked. Boot bakes every `LOOKS` id, so it only happens to ids added later. Speaker ids that are not look ids (TWO's
`manager`, `figure`) need an explicit mapping (§13.1).

### 13.9 Pitfalls checklist

1. **Skip-safety.** Every new UI step returns immediately (or resolves next tick) while `flow.skipping`. Every
   `waitUntil` loop returns `true` on `flow.skipping`. Every `do` that opens a pop-up or card checks
   `c.flow.skipping` first. Button-less pop-ups need `dur` or an explicit `close()`. Cards opened in `do` need
   `ui.card(null)`.
2. **No per-frame allocation** in anything added to `ui.update`, `popup.render` or a `render` listener: preallocate
   vectors, cache strings, compare before writing to the DOM, never read layout (`getBoundingClientRect`) per tick.
3. **Pool DOM** (barks, SafeSense windows, AR labels, HUD parts) and create it at boot behind the loader.
4. **Warm-up at boot.** Every speaker portrait is baked (or explicitly a silhouette) so `buildCharacter` never runs
   mid-game. The title set is in `SETS` so `world.warm` compiles it. Card painters are cheap but `polaroid`-style ones
   allocate canvases: paint on change.
5. **One dialogue request at a time.** Barks use their own box. `say` inside `par` with another `say` resolves the first.
6. **Input precedence.** Dialogue and the top buttoned pop-up consume YES before hotspots and minigames (they run
   first in the tick). Open menus consume every action. While `say.busy()`, pop-ups ignore keys.
7. **NO is overloaded**: fast-forward in cutscenes, answer for `ask`, Cancel for pop-ups (outside cutscenes), close for
   the inventory, back in menus. Keep TWO's NO mechanics (hold NO in 3.6, the hack bar, Pop-up drones) out of
   cutscenes.
8. **TDZ.** Leaves (sets `10-29`) evaluate before `31-ui.js`: no top-level `ui`/`say`/`popup` references in a set file,
   and do not define built-in `CARDS` names there (they get overwritten).

## 14. The ten gotchas most likely to bite

1. The inventory panel freezes `say.update` and `popup.update`: a pending line or pop-up cannot finish, even when skipping (152).
2. `say.busy()` blocks keyboard input to pop-ups. Pop-ups opened during dialogue wait for it (501).
3. Pop-up input goes to the **newest** buttoned pop-up, NO only presses a button labelled `'NO'`/`'Cancel'`, and NO is
   ignored during cutscenes (508-509).
4. `buttons: []` pop-ups never close by themselves, and are not auto-closed by skipping (495).
5. `popup().el` is pooled: after `done`, it may already be another pop-up. Undo any DOM changes you made to it.
6. Cards shown with `ui.card` from a `do` step are not cleared by flow. There is no `{ card }` step; cards ride on `shot`s.
